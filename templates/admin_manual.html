1. 角色与系统组成

  • user：普通用户，只能使用自己的数据与索引
  • admin：管理员，可管理普通用户相关资源
  • super_admin：超级管理员，可进一步管理管理员账号

当前项目由 3 个核心部分组成：

  • Flask 主应用：负责页面、认证、业务接口与 RAG 编排
  • MySQL：保存用户、数据集、索引记录、构建任务和审计日志
  • 独立 FAISS 服务：负责向量索引构建、检索和可视化数据读取
普通用户无法自助提升为管理员。管理员账号应由项目维护者预置和分发；如果需要公开发布，建议同时准备用户手册、管理员与开发者手册以及 `.env.example`。

2. 部署与依赖

推荐的本地部署顺序如下：

  1. 复制 `.env.example` 为 `.env` 并填入真实值
  2. 启动 Docker 依赖服务：docker compose up -d --build mysql faiss
  3. 安装主应用依赖：pip install -r requirements-app.txt
  4. 如需运行数据处理或知识索引脚本，再安装：pip install -r requirements-tools.txt
  5. 构建知识索引：python scripts/build_knowledge_index.py --batch-size 256 --log-dir logs --resume
  6. 启动主应用：python app.py

依赖文件按用途拆分为：

  • requirements-common.txt：主应用与 FAISS 服务共享基础依赖
  • requirements-faiss.txt：FAISS 服务专用依赖
  • requirements-app.txt：主应用额外依赖
  • requirements-tools.txt：脚本与数据处理依赖
`Dockerfile.faiss` 只安装 FAISS 服务需要的依赖，避免把 RAG 和脚本依赖一起塞进向量服务镜像；`.dockerignore` 也应排除 `data/`、`knowledge/` 等大目录，减少构建上下文体积。

3. 环境变量与安全

部署者应从 `.env.example` 开始配置环境变量，而不是把真实密码或 API Key 写死在代码里。

  • DATABASE_URL：Flask 主应用连接 MySQL 的地址
  • MYSQL_PASSWORD：MySQL 用户密码
  • MYSQL_ROOT_PASSWORD：MySQL root 密码
  • SECRET_KEY：登录令牌签名密钥
  • ZHIPU_API_KEY：AI 助手所需的大模型密钥
  • FAISS_SERVICE_URL：Flask 主应用调用 FAISS 服务的地址
  • SEWORK_KNOWLEDGE_INDEX_DIR：知识索引输出目录，默认是 knowledge/index
  • SEWORK_USER_KB_PATHS：用户扩展知识文件路径

当前 `docker-compose.yml` 中的 MySQL 密码已改为环境变量引用：

MYSQL_PASSWORD: ${MYSQL_PASSWORD:-sework2024}
MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-root2024}
`.env` 已加入 `.gitignore`。真实密码、数据库连接串、智谱 API Key 不应上传到 GitHub；如果仓库中历史上已经提交过真实密钥，建议立刻旋转密码和 API Key。

4. 知识库与 RAG

当前 RAG 主链路主要服务于 POST /api/ai/cell-query。它不是单纯的大模型问答，而是：

  • 先解析自然语言中的 cell_type、disease、tissue 等线索
  • 再检索本地知识库中的概念、marker、说明文档
  • 随后结合当前活动索引或候选结果召回相关细胞
  • 最后融合知识证据与数据证据生成解释性回答

推荐的知识库目录结构如下：

knowledge/
├── index/
│   ├── knowledge.faiss
│   └── metadata.json
├── source/
│   ├── README.md
│   ├── sc_knowledge.jsonl
│   ├── sc_concepts.jsonl
│   ├── cell_marker_kb_filtered.jsonl
│   ├── cell_marker_kb.jsonl
│   └── user/
└── examples/
    └── demo.jsonl

CPU 环境下推荐优先使用精简版知识库：

  • cell_marker_kb_filtered.jsonl：36,401 条，CPU 构建索引约 1.5 到 2 小时
  • cell_marker_kb.jsonl：123,170 条，CPU 构建索引约 24 小时

推荐命令：

# 推荐正式构建命令：生成持久化日志，并在存在兼容 checkpoint 时自动恢复
python scripts/build_knowledge_index.py --batch-size 256 --log-dir logs --resume

# 仅诊断：先确认文档数量、模型加载、设备和文本长度统计
python scripts/build_knowledge_index.py --diagnose-only --log-dir logs

# 指定 checkpoint 目录，便于多次恢复同一轮长任务
python scripts/build_knowledge_index.py --batch-size 256 --log-dir logs --checkpoint-dir knowledge/index/.checkpoint --resume

# 精简知识库生成脚本
python scripts/filter_cell_marker_kb.py --aggressive --output knowledge/source/cell_marker_kb_filtered.jsonl
从当前版本开始，build_knowledge_index.py 会将日志持久化到 logs/knowledge-index-*.log，并在 knowledge/index/.checkpoint/ 下保存 checkpoint。推荐优先使用带 --log-dir logs --resume 的命令，避免长时间构建失败后既无记录也无法恢复。
如果 `knowledge/source/` 中不存在对应文件，系统会回退读取旧的 `data/kb/`。这保证了兼容性，但对公开发布而言，推荐尽量迁移到新的 `knowledge/` 结构。

5. 后台管理操作

管理员登录后，在历史页可看到 Admin Dashboard。总览区域重点指标包括：

  • 用户总数、启用账号、停用账号和管理员数量
  • 数据集总数、索引总数、失败任务数和进行中任务数
  • 索引类型分布、距离度量分布、构建趋势和用户索引 Top 10

5.1 用户管理

  • 创建普通用户，超级管理员可进一步创建管理员
  • 修改显示名、邮箱、启用状态和角色
  • 重置密码，处理账号交接或遗忘密码问题
  • 删除用户前，先确认其数据集和索引是否仍在使用

5.2 数据集管理

  • 查看所有数据集的来源、格式、细胞数、维度和状态
  • 排查失效路径、异常格式和归属问题
  • 删除不再使用或错误导入的数据集

5.3 索引管理

  • 查看索引所属用户、关联数据集、索引类型、距离度量和构建参数
  • 强制激活某个索引，帮助用户恢复工作环境
  • 删除错误、失效或不再使用的索引

6. 构建任务监管

管理员可查看索引构建任务的：

  • 所属用户
  • 目标数据集
  • 索引名称
  • 状态与阶段
  • 更新时间

当出现构建失败时，可优先检查：

  • MySQL、FAISS 容器是否正常启动
  • .env 中的 DATABASE_URL 和 FAISS_SERVICE_URL 是否正确
  • 数据文件是否被容器正确挂载
  • 知识索引是否已重新构建，尤其是在修改 knowledge/source/ 后

7. 管理员初始化

若系统尚无管理员账号，可由部署者在项目根目录执行：

python scripts/bootstrap_admins.py

脚本默认会处理以下账号：

  • admin01
  • admin02
  • admin03
  • admin04

其中第一个账号默认会被设置为 super_admin。脚本也支持通过环境变量自定义管理员列表、超级管理员账号和密码。

8. 审计与运维建议

审计日志用于记录关键后台操作，便于答辩展示、责任追踪和问题回溯。典型记录包括：

  • 创建用户、修改角色、停用或启用账号
  • 重置密码、删除数据集、删除或强制激活索引

日常运维建议：

  • 先看总览，再进入用户、数据集和索引细查问题
  • 删除用户或数据集前，先确认是否仍在演示流程中使用
  • 对管理员账号的增删改操作，尽量由超级管理员执行
  • 知识库文件更新后，及时重新执行知识索引构建
  • 如需面向普通用户答疑，请优先引导其查阅用户手册和 RAG 实现文档

9. 常见问题

9.1 登录时报数据库连接错误

请先检查 `ann-mysql` 是否正常启动，`.env` 中的 `DATABASE_URL` 是否正确，以及 MySQL 映射端口是否与 `docker-compose.yml` 一致。

9.2 AI 助手不可用

优先检查是否配置了 ZHIPU_API_KEY，以及是否已执行 python scripts/build_knowledge_index.py --batch-size 256 --log-dir logs --resume 生成知识索引。

9.3 知识索引构建过慢

CPU 环境下请优先使用 cell_marker_kb_filtered.jsonl，并显式传入 --batch-size 256 --log-dir logs --resume；如仍过慢，可先执行 python scripts/filter_cell_marker_kb.py --aggressive 重新生成精简知识库。正式重跑前也建议先用 python scripts/build_knowledge_index.py --diagnose-only --log-dir logs 做一次轻量诊断。

9.4 仓库中发现明文密码或密钥

立即将其改为 `.env` 中的环境变量引用，旋转数据库密码和 API Key，并确认 `.env`、知识索引产物、用户数据文件均已加入 `.gitignore`。
